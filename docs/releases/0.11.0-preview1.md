# WindowsDeviceLink 0.11.0-preview1

This preview simplifies authentication and adds structured tenant configuration for
both the Direct-mode GUI and the Azure Function backend.

## Direct mode

- Direct mode now supports only delegated operator authentication: **Interactive**
  (WAM) and **DeviceCode**.
- Certificate and client-secret authentication have been removed from the public
  device-side workflow. Unattended operation belongs behind the Function backend so
  Graph credentials do not need to be distributed to devices or WinPE images.
- The optional `Show-WindowsDeviceLink -Configuration` input accepts inline JSON, a
  local JSON file, or an HTTPS URL.
- Direct-mode configuration can describe one tenant, separate app registrations per
  tenant, or a shared multitenant app registration.
- Configuration is intentionally a GUI convenience. Public CLI commands continue to
  use explicit tenant, client and authentication parameters.

## Backend mode

- `WINDOWSDEVICELINK_CONFIGURATION_JSON` is the authoritative tenant and authentication
  profile configuration for the Azure Function backend.
- Multiple tenants can share one multitenant app registration or reference separate
  tenant-scoped authentication profiles.
- Backend profiles support certificate authentication and client-secret authentication.
  Credential values remain in Key Vault-backed Function App settings and are referenced
  by setting name from the JSON configuration.
- Lookup, registration, reconciliation, move and offboarding resolve authentication for
  the tenant involved in each operation.
- The API-key boundary remains unchanged. Restricting API access at the network layer and
  retrieving short-lived or frequently rotated API keys outside WinPE images remain the
  recommended deployment practices.

## Public surface

- The newly introduced `Get-WindowsDeviceLinkTenantCatalog` command has been removed.
- `Get-WindowsDeviceLinkBackendTenant` remains the public way to retrieve the backend's
  tenant catalog and capabilities.
- Existing association state, Function endpoint and DeviceLink firmware contracts remain
  unchanged.

## Documentation and examples

- Added Direct-mode configuration guidance and generic single-tenant, per-tenant app and
  shared-app examples.
- Added backend configuration guidance and generic shared-app and tenant-app examples.
- Updated authentication and hardening guidance around the delegated Direct-mode and
  credential-isolated Backend-mode boundary.

## Compatibility

This is a preview release and intentionally does not provide a migration layer for the
superseded authentication configuration. Review the new configuration documentation
before deploying the updated Function App or using Direct-mode GUI configuration.
