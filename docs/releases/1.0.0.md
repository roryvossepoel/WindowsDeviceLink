# WindowsDeviceLink 1.0.0

The first stable WindowsDeviceLink release brings the tested CLI and operator GUI
workflows together for Windows Autopilot Device Preparation Device Association.

## Included workflows

- Generate a TPM-backed DeviceLink identity, export the Windows-generated CSV and
  inspect local firmware and cloud association state.
- Pre-associate a device before enrollment; complete its local association on
  supported full Windows; remove cloud records and reset local state with explicit
  confirmation and post-operation checks.
- Use Direct mode with Interactive or DeviceCode authentication, including multiple
  configured tenants. Configuration can be inline JSON, a local file or trusted HTTPS.
- Use Backend mode for centrally managed authentication and multitenant operations,
  including tenant Move. Backend mode remains the recommended multitenant route.
- Inspect runtime support, health, readiness, local tenant metadata and safe repair
  plans without automatically performing repair actions.

## Changes since 0.12.1-preview1

- Fixed single-tenant configuration display and selection in Windows PowerShell 5.1.
- Direct sign-out immediately unlocks the tenant selector, clears the account and
  cached cloud result, and shows Not checked in the cloud card.
- With multiple configured tenants, sign-out returns the selector to Select target
  tenant...; a fixed single tenant is retained. Both Interactive and DeviceCode use
  this behavior.
- The GUI title now shows Preview only for prerelease builds.
- Stable installation examples no longer require `-AllowPrerelease`.

The signed-out Direct local-reset flow from 0.12.1-preview1 remains available for
Interactive and DeviceCode. Its confirmation warns that no cloud check is performed
and cloud registration may remain. Backend local-reset gating is unchanged.

## Install or upgrade

Run in an elevated native Windows PowerShell 5.1 session:

```powershell
Install-Module WindowsDeviceLink -Repository PSGallery -RequiredVersion 1.0.0 -Force
Import-Module WindowsDeviceLink -RequiredVersion 1.0.0 -Force
Show-WindowsDeviceLink
```

## Validation and support boundaries

The 2026-10-02 Windows 11 AMD64 session covered GUI/CLI authentication and lifecycle
operations, configuration loading, tenant switching and final sign-out behavior.
Earlier physical ARM64 full-Windows and AMD64 WinPE/Backend results remain tied to
their recorded builds. See the detailed
[test evidence](https://github.com/roryvossepoel/WindowsDeviceLink/blob/v1.0.0/TESTING.md)
and [validation checklist](https://github.com/roryvossepoel/WindowsDeviceLink/blob/v1.0.0/docs/VALIDATION-CHECKLIST.md).
These records distinguish live checks, automated coverage and deferred scenarios.

- Native 64-bit Windows PowerShell 5.1 is required. Full Windows AMD64 and ARM64 use
  the supported registered Windows runtime.
- AMD64 WinPE supports pre-association with a compatible administrator-supplied
  runtime DLL. Native association completion requires supported full Windows.
  ARM64 WinPE and x64-emulated PowerShell on ARM64 remain unsupported.
- No Microsoft runtime DLL is bundled. The module remains unsigned; the documented
  WinPE publisher-check workaround still applies where needed.
- The stable module label does not change the status of its dependencies: native
  operations use undocumented Windows Runtime interfaces and cloud operations use
  Microsoft Graph beta APIs. Production support guarantees are outside scope.
- Association JWT checks do not perform cryptographic signature validation.
- Manual Azure backend deployment is supported; the Bicep/ARM deployment route
  remains experimental. Device preparation policy assignment is outside scope.

See the [installation guide](https://github.com/roryvossepoel/WindowsDeviceLink/blob/v1.0.0/docs/INSTALLATION.md)
for WinPE preparation and upgrade troubleshooting.
